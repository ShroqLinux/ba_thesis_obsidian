
In distributed systems, there are several redundancy types and the choice depends on the target of a system's design. As Steen (2025) describes, information redundancy is done by adding bits to the data itself to enable recovery and error detection, e.g. using Hamming codes. This is more efficient and requires less storage compared to full data replication.

Spatial redundancy focuses on physical components in two possible ways. The extra components are used where the primary components fail. One example here is to keep an active spare ready that is ready to use at all times, which can be computationally costly. Djambazova (2023) addresses one example where a system using Triple Modular Redundancy (TMR) can transition to Dual Modular Redundancy (DMR), where upon failure of one redundant node, the system can gracefully degrade to use two of the original three nodes in a cluster. For this, the nodes must be able to self-check to identify which node is faulty (Djambazova, 2023).

The second method for spatial redundancy is passive replication, where active primaries relay information to cold standbys. Cold nodes are activated on-demand when a primary node is faulty.

Temporal redundancy compensates for the effects of transient faults and uses re-executing a program or retransmission of data when an error occurs (Djambazova, 2023), e.g., retransmission timeout in TCP communication (Tanenbaum, 2003).
