_Note 3/11_

The use case that will be the focus of this thesis is Suppression of Enemy Air Defence (SEAD). SEAD is a mission type that aims to enable friendly air superiority and freedom of movement by disruption or destruction of enemy air defence. Enemy threats advance faster and require an answer through technological developments on friendly side as well. An increase in the complexity of how interwoven these systems using robotics, virtual reality, etc., require new methods in implementing solutions too. (McLaughlin et al., 2018)
Here it will be analyzed for the domain of avionic systems how AI planning can be used in the context of SEAD. The domain constraint of avionics necessitates determinism in safety-critical systems. A common challenge in safety-critical systems is component or system failure, which requires foresight in the design phase during development and an approach must be defined to mitigate its effects with recovery and fallback mechanisms. Software systems in avionics commonly use triple-modular redundancy (TMR) already which creates the possibility to use HTNs with an established redundancy solution.

_Note 5/11 Reason for HTN_

HTN is well suited in domains where hierarchical representation is desirable (Georgievski and Aiello, 2015). (To be formulated further) Attach it further to existing examples of hierarchical structures within military tasks across several levels in strategy, operations and tactics. The match in paradigm of planning and the existing structure are in good agreement.

The goal of a distributed architecture in a broader context is to have some benefit through system capabilities which a single unit solution cannot fulfill. A single hierarchical task network (HTN) system is also a single point of failure (SPOF), this applies to any system that is implemented as only one component. Since the writing is focused specifically on safety-critical systems, the main question is how coordination can be done effectively for a redundantly designed HTN. This entails relevant components, their capabilities and trade-offs for real-world implementations.

_Note 15/10/26: MBSE method of work, system definition_

The next step is to state *how* the system-level problem of a SPOF can be solved, which is done by introducing triple modular redundancy (TMR). The decision for TMR is rooted in the common use within avionic and other safety-critical domains, this applies to both hardware and software systems. Hence the architecture defines no restriction on a concept level of how TMR is realized in its technical implementation, both software and hardware may be viable depending on the specific system.
