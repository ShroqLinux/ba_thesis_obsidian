The goal of a distributed architecture in a broader context is to have some benefit through system capabilities which a single unit solution cannot fulfill. A single hierarchical task network (HTN) system is also a single point of failure (SPOF), this applies to any system that is implemented as only one component. _(Note 11/11)_ Redundancy engineering is a method to design fault-tolerant systems that can continue their expected normal operation when an error occurs. It must also be clarified here how the terms failure, fault and error are used in redundancy. As it is stated by Koren and Krishna (2021:, p.1), 'A _fault_ (or _failure_) can be either a hardware defect or a software/programming mistake (bug). In contrast, an _error_ is a manifestation of the fault/failure/bug.'
Since the writing is focused specifically on safety-critical systems, the main question here is how coordination can be done effectively for a redundantly designed HTN. This entails relevant components, their capabilities and trade-offs for real-world implementations.

In distributed systems, there are several redundancy types and the choice depends on the target of a system's design. As Steen (2025) describes, information redundancy is done by adding bits to the data itself to enable recovery and error detection, e.g. using Hamming codes. This is more efficient and requires less storage compared to full data replication.

Spatial redundancy focuses on physical components in two possible ways. The extra components are used where the primary components fail. One example here is to keep an active spare ready that is ready to use at all times, which can be computationally costly. One example is a system using Triple Modular Redundancy (TMR) that can transition to Dual Modular Redundancy (DMR), where upon failure of one redundant node, the system can gracefully degrade to use two of the original three nodes in a cluster. For this, the nodes must be able to self-check to identify which node is faulty. (Djambazova, 2023)

Another method for spatial redundancy is passive replication, where active primaries relay information to cold standbys. Cold nodes are activated on-demand when a primary node is faulty. (Djambazova, 2023)

Temporal redundancy compensates for the effects of transient faults and uses re-executing a program or retransmission of data when an error occurs (Djambazova, 2023), e.g., retransmission timeout in TCP communication (Tanenbaum, 2003).
