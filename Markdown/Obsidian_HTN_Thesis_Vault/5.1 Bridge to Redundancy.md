The goal of a distributed architecture in a broader context is to have some benefit through system capabilities which a single unit solution cannot fulfill. A single hierarchical task network (HTN) system is also a single point of failure (SPOF), this applies to any system that is implemented as only one component. _(Note 11/11)_ Redundancy engineering is a method to design fault-tolerant systems that can continue their expected normal operation when an error occurs. It must also be clarified here how the terms failure, fault and error are used in redundancy. As it is stated by Koren and Krishna (2021:, p.1), 'A _fault_ (or _failure_) can be either a hardware defect or a software/programming mistake (bug). In contrast, an _error_ is a manifestation of the fault/failure/bug.' With any complex software, it is known that there is no software that is "bug-free" (Smith et al., 2018). This also means that redundant solutions don't aim to fully eliminate a fault in a system and instead are used to compensate for the event of an error or a bug.

There are several redundancy types and the choice depends on the target of a system's design. Here it will first be shortly described what techniques there are and where they are used. As Steen (2025) describes, information redundancy is done by adding bits to the data itself to enable recovery and error detection, e.g. using Hamming codes or cyclical redundancy check (CRC) (Tsimbalo et al., 2015). This is more efficient and requires less storage compared to full data replication.
Time redundancy compensates for the effects of transient faults and uses re-executing a program or retransmission of data when an error occurs (Djambazova, 2023), e.g., retransmission timeout in TCP communication (Tanenbaum, 2003).

Structural redundancy focuses on adding software or hardware components in two possible ways: hot and cold spares (Djambazova, 2023). The extra components are used where primary components fail. Hot spares are ready to use at all times, which can be computationally costly. Cold standby spares become active when a primary fails (Djambazova, 2023). Cold nodes would need to be synchronized with data and current state in execution of the active primaries.

Since the writing is focused specifically on HTN in a safety-critical system, the main question here is how coordination can be done effectively for a redundantly designed HTN. This entails relevant components, their capabilities and trade-offs for real-world implementations. The relevance of TMR was mentioned in the introduction already which is why it will be described closer here.
TMR is a type of M-out-of-N system. These require a minimum of M functional modules in a system that consists of a total of N modules. Each individual module computes an identical process whose results are then compared by a voter. The voter validates the result as 'matching' so long as the majority (2 out of 3) produce results that agree. Another term for a TMR is the triplex. (Koren and Krishna, 2021)
This means individual faults of a node are masked by the voter and a system sees its operation as 'correct' despite it. Two weaknesses can emerge based on this property. If the software or another process (TMR can also be used as a hardware-only system (Mukherjee and Dhar, 2019)) has a fault by design, the voter compares incorrect output as 'matching' which it wrongly rates as 'correct'. The second problem which will be described here is when a node failure occurs and only two remaining nodes are still operational. In this case, a voter can detect either two matching outputs or differing outputs, but cannot identify which node is faulty due to lack of a majority. Similar problems in lack of majority have been researched (Shin and Hagbae Kim, 1994). This will also be considered in the limitations of the concept that will be described later.

An example for structural redundancy is a system using Triple Modular Redundancy (TMR) that can transition to Dual Modular Redundancy (DMR). Upon failure of one redundant node, the system can gracefully degrade to use two of the original three nodes in a cluster. (Djambazova, 2023)
