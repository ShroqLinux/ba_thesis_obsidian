

_Note 30/10/26: possible ideas on second resolution_

For the resolution using a plausibility score, a weighted average will be used here. A single weight can be used for high probability cases and double weightage will be given to low probability cases. The effect of the latter intentionally lowers the score significantly to allow for a rejection of the voter's result. Repeating the same input wouldn't yield a different result however, which is also this method's limitation because of DFS' deterministic behavior. For this method, the only resolution which is to be used is a confirmation or rejection to maintain focus on node failure and system recovery here.

Next is the state of Failure where detection and response need to be defined. In a distributed system, the use of heartbeat messages is a common method for this to determine liveness of a component in the system. One example for this is described in Steen et al. (2025) in Raft where a leader signals its followers by regularly sending messages to tell it is still active and operational. The same logic will be used here where the worker nodes periodically send a message to signal their liveness. A timer expiration can be used if after the last message no further response is received for a defined duration. When the timer has expired, it is assumed that the corresponding node is unresponsive and therefore a failure has occurred. Then other components must be signaled of the failure with a broadcast message to halt current execution.
