# Introduction to Hierarchical Task Networks

HTN is a paradigm in AI planning for automated planning. Classical planning focuses on finding sequence to get from point A to point B, while Hierarchical Task Networks focus on high-level decomposition until high-level tasks become manageable, directly executable subtasks (Nau et al., 2003). Three key components within HTN are tasks, methods, initial state and a goal. 

Tasks are the “what” of the plan. Primitive tasks are basic actions that can be executed in the environment. Non-primitive tasks are compound tasks, these are high-level tasks composed of several primitive tasks. Methods are the “how” and are the recipe telling the planner how to decompose a specific task into sub-tasks. The initial state describes the world at the beginning. Decomposition is done recursively by the planner and stops when it has found a task set that can be directly performed by *planning operators* (Nau et al., 2003).

Two planners that serve as a starting point for introduction into this subject are SHOP and SHOP2. SHOP is “Simple Hierarchical Ordered Planner” which decomposes tasks recursively into directly executable primitive tasks exactly in the order they are to be executed. This significantly reduces complexity in the decision making for task sequences. SHOP2 adds the possibility of partial ordering where subtasks from different compound tasks can be interleaved (Nau et al., 2003). There are many more planners which use other methods, e.g. stochastic or heuristics. 
SHOP planners use a DFS-style search through their decision trees which provides a deterministic search algorithm. The frame here is restricted to use SHOP planners because of their simplicity, where the main topic becomes the parallelization of the search itself and in which variants this is possible. There are several options with SHOP for the stopping condition, by default this would be at the first valid solution plan that is found. SHOP can be configured to explore an entire task tree and return all possible plans for a given task. As Nau et al. (2003) defines, it's possible for SHOP2 to use Branch-and-Bound Optimization where the planner doesn't stop at the first valid plan that's found. Instead, it searches for a least-cost or optimal plan. This can be useful when optimization is a system requirement.

A lot of literature primarily focused on theoretical foundations on HTN. Less focus on solutions for application contexts. Conventionally, HTN is used within single core, single computer systems. The question to solve is what possible implementation can be used for a distributed system. A starting point is provided through [GTPyhop](https://github.com/dananau/GTPyhop/tree/main), an open source planning system by Dana Nau from University of Maryland.  
Classically, HTN is best suited for deterministic, closed-world systems which has already been extensively studied due to focus on planners rather than actors as stated in this paper from 2014. [1-s2.0-S0004370213001173-main.pdf](https://drive.google.com/file/d/1DlHenoNkVu2mb9aOMb210BqF8Dp3SHsH/view?usp=drive_link) Many real-world systems operate in dynamically changing environments requiring continuous adaptation in planning and decision making.
