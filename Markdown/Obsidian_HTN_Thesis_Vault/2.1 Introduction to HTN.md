
## Hierarchical Task Networks

Hierarchical Task Network (HTN) is a paradigm in AI planning for automated planning. Classical planning focuses on finding sequence to get from point A to point B, while Hierarchical Task Networks focus on high-level decomposition until high-level tasks become manageable, primitive subtasks (Nau et al., 1999). Four key components within HTN are tasks, methods, initial state and a goal. Tasks are the *what* of the plan. Primitive tasks are basic actions that can be executed in the environment. Non-primitive tasks are compound tasks, these are high-level tasks composed of several primitive tasks. Methods are the *how* and are the recipe telling the planner how to decompose a specific task into sub-tasks. The initial state describes the world at the beginning. Decomposition is done recursively by the planner and stops when it has found a task set that can be directly performed by *planning operators*. The goal is itself a compound task and serves as the starting point for decomposition (Nau et al., 2003).

Two planners that serve as a starting point for introduction into this subject are SHOP and SHOP2. SHOP is "Simple Hierarchical Ordered Planner" which decomposes tasks recursively into directly executable primitive tasks exactly in the order they are to be executed. This significantly reduces complexity in the decision making for task sequences because the planner knows at each step the current state of the world, thus removing uncertainty in planning. SHOP2 adds the possibility of partial ordering where subtasks from different compound tasks can be interleaved (Nau et al., 2003) which means that the sequence of executing their subtasks is not strictly a total order and can be mixed. In total order, one compound task must be fully decomposed and solved before the next one can be solved by the planner. There are many more planners which use other methods, e.g. stochastic or heuristics.
SHOP planners use depth-first search (DFS) in the traversal of their task trees, which provides a deterministic search algorithm. The frame here is restricted to use SHOP planners because of their simplicity, where the main topic becomes the parallelization of the search itself and in which variants this is possible. There are several options with SHOP for the stopping condition, by default this would be at the first valid solution plan that is found. SHOP can be configured to explore an entire task tree and return all possible plans for a given task. As Nau et al. (2003) define, it is possible for SHOP2 to use Branch-and-Bound Optimization where the planner does not stop at the first valid plan that is found. Instead, it searches for a least-cost or optimal plan. This can be useful when performance optimization is a system requirement.
