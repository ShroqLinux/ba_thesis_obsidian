# Hierarchical Task Networks

Hierarchical Task Network (HTN) is a paradigm in AI planning for automated planning. Classical planning focuses on finding sequence to get from point A to point B, while Hierarchical Task Networks focus on high-level decomposition until high-level tasks become manageable, primitive subtasks \parencite{nau_shop_1999}.
Four key components within HTN are tasks, methods, initial state and a goal. Tasks are the *what* of the plan. Primitive tasks are basic actions that can be executed in the environment. Non-primitive tasks are compound tasks, these are high-level tasks composed of several primitive tasks. Methods are the *how* and are the recipe telling the planner how to decompose a specific task into sub-tasks. The initial state describes the world at the beginning. Decomposition is done recursively by the planner and stops when it has found a task set that can be directly performed by *planning operators*. The goal is itself a compound task and serves as the starting point for decomposition. Two planners that serve as a starting point for an introduction into this subject are SHOP and SHOP2. SHOP is “Simple Hierarchical Ordered Planner” which decomposes tasks recursively into directly executable primitive tasks exactly in the order they are to be executed. This significantly reduces complexity in the decision making for task sequences because the planner knows at each step the current state of the world, thus removing uncertainty in planning. SHOP2 adds the possibility of partial ordering where subtasks from different compound tasks can be interleaved which means that the sequence of executing their subtasks is not strictly a total order and can be mixed. In total order, one compound task must be fully decomposed and solved before the next one can be solved by the planner. \parencite{nau_shop2_2003}
There are many more planning techniques which use other methods, e.g. probabilistic (Sherkat, Wortmann and Wortmann, 2025) or heuristics (Georgievski and Aiello, 2015). 

A simple example will be defined here to illustrate how a HTN can be defined for a drone and the tasks it must fulfill.

SHOP planners use depth-first search (DFS) algorithm in the traversal of their task trees (Nau et al., 1999), which provides a deterministic search algorithm when used with a fixed adjacency structure (Lammich & Neumann, 2015) and a fixed starting vertex. An adjacency list, as defined by Tarjan (1971), contains all vertices $w$ such that $(v,w) \in E$ of a graph $G = (V,E)$ with $V$ vertices and $E$ edges. In other words, an adjacency list contains all the neighbors of one vertex $v\in V$. An adjacency structure contains all adjacency lists of a graph $G$. (_Note 9/11)_ In practical application, what follows is that a SHOP planner runs a defined list of tasks and methods in an order set during offline development, which may be required when multiple methods must be searched when given a complex initial world state. The reason to use SHOP in this writing is because DFS creates reproducible outcomes under the defined conditions and SHOP's total order imposes a reproducible process in its preceding steps, which aligns in principle to the definition of determinism as stated in EASA (2022, Sec. 4) in regard to the repeatability of outcome. There are several options with SHOP for the stopping condition, by default this would be at the first valid solution plan that the planner found or SHOP can be used to explore an entire task tree and return all possible plans for a problem (Nau et al., 1999). As \textcite{nau_shop2_2003} define, it is possible for SHOP2 to use Branch-and-Bound Optimization where the planner does not stop at the first valid plan that is found. Instead, it searches for a least-cost or optimal plan.

SHOP will be used in the concept development here because of its simplicity in functional logic and is a good fit to serve as an example.
