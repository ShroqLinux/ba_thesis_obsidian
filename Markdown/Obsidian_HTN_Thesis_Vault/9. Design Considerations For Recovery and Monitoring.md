# Design considerations for recovery and monitoring

_Note 28/08/26: Reviewing some critical points with Gemini Pro_

**

Following the point of system design and monitoring methods, Gemini did scrutinize how the semantic logic of a watchdog would work. Watchdog timers are useful to determine when a program might have missed a deadline and must be terminated to avoid indefinite execution times. They serve well as a timeout.

The criticism was a fair point on determining how WCET can be calculated considering that most AI planners are difficult to estimate on this (e.g.  stochastic planners) can grow exponentially.

This is reduced by design as SHOP2 uses a DFS-style search in the task tree. Its termination for a state “success” of having found a solution is only contingent on finding the first possible solution with a set of tasks irrespective of whether it’s the most efficient one or not. The SHOP planners don’t continue searching or comparing multiple solutions. In addition to this, DFS is a deterministic search algorithm so that an engineer can determine during offline development the true WCET and add a buffer ε to determine the limit required for a watchdog timer when defining a task network for a static, closed-world system. One point that requires further analysis is how a watchdog timer’s base calculation must be defined.

_Note 22/09/26: Watchdog timer duration_

One possibility is to use an empirical approach by calculating the median of all WCET and adding a buffer ε for the timer duration. This wouldn't be applicable to real-time systems which are safety-critical.
Another approach would be to use the upper-bound limit of maximum depth in the task tree of longest execution time possible which is possible here as the task tree is defined offline and DFS is deterministic. This can be paired with the number of steps required to execute through the entire task tree and number of CPU cycles required to execute the instruction steps. For a simpler demonstration example in the PoC later this might be out of scope and instead the empirical approach can be used on a large sample size. The implementation PyHOP is developed in Python and a statistical approximation can suffice to demonstrate how the system can respond when a watchdog timer triggers.
