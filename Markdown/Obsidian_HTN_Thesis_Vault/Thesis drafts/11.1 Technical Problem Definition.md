Using the model above, it is simpler to show what role TMR has as the process which mitigates a possible SPOF in a system view. Input would come from other systems, e.g. sensors, sub-systems, etc., and needs to be received by the process. The process then passes forward its output to other sub-systems, e.g. actuators.

The first question considers what is actually to be solved for with the design and which aspects have been previously developed. This follows the principle in requirements engineering on the left side of the V-model and is a start for the problem and target definition.
Both coordination and communication in distributed computing have been extensively researched, Lamport (1978) laid the foundation for logical clocks, "happened before" relation and vector clocks. Same can be said about lower level communication including but not limited to Remote Procedure Calls (RPC) and Remote Method Invocations (RMI) (Tanenbaum and Van Steen, 2017). This shifts the focus of the problem from coordination and communication which is relevant to the foundational concepts of distributed computing, to the question of how coordination and communication need to be designed for a redundantly designed HTN. Here it is necessary to specify which target the redundant design needs to fulfill, which allows the derivation of the functional logic of coordination. The target serves as the system-level goal while the coordination is a means to said goal.
For this writing, the target of the system is defined to mitigate the failure of a node in the TMR cluster by restarting the affected node.
