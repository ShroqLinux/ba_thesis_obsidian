The previous chapters introduced the concepts relevant to this thesis: HTN planning and redundancy through replication. This chapter combines them into an architecture concept for a redundant planning cluster. Before the concept is developed, the following section defines which of these concepts it builds on and what assumptions it makes, as these determine the conditions under which the architecture is valid.

DFS is a deterministic search algorithm in good agreement with behavior per-node in a cluster of redundant nodes which run a HTN with SHOP. The reproducibility of both a deterministic process and outcome allow for a diagnosis or determination of an error when either differ from their expected behavior at runtime. This is beneficial to the design process as expected behavior can be defined offline and compared against observed behavior at runtime, so failures and recovery can be specified in advance during development.

While determinism ensures consistent behavior within each node, the cluster as a whole must also be predictable. In a statically configured system, the set of relevant data, participants and information are fixed and known. This means for network behavior and topology that a static cluster will be considered because it allows for full offline definition of the cluster at time of design and development for any mechanisms which TMR and HTN requires.

Connecting this to the topic of communication within the nodes is the possibility of errors in either transmission medium or the message itself even at successful delivery at the recipient. While message delivery is defined as guaranteed between sender and recipient, it is still possible that errors occur on a bit-level due to electromagnetic variance or hardware problems in electronic components, e.g. CPU, RAM, a bus system or other which aren't a fault of the actual transmission itself. The guarantee for message delivery is assumed based on the existing standards for avionic buses, e.g. MIL-STD-1553 (MIL-STD-1553C, 2018) which defines mechanisms for retransmission and bit-level correction like parity bits, Manchester II, etc.

The next design decision concerns the type of redundancy considered. Triple modular redundancy will be used as it's a foundational concept used widely in many safety-critical domains including but not limited to avionic, automotive, medical systems as stated earlier. The goal of the design concept is to enable fault-tolerance and resilience. The last part currently excluded for concept development are advanced architectures which make use of TMR as one component of the redundancy model. Focus will instead be put on concepts from these architectures to a more basic model.

As a method of work, some principles from systems engineering will be used to serve as a framework to guide the process to find a solution concept. The main focus of systems engineering is to focus on the system as a whole. It is relevant to consider which interactions take place both with external systems as well as internally in the system of interest. Other external factors are the customer's (or user's) needs, interfaces, capabilities of the system for the user and more which must be included in a system's design. One approach of systems engineering is the V-Modell which encompasses many steps from the definition of requirements to high-level design, detailed design and on the right side system verification and validation. These stages will also be used here as a reference. (Kossiakoff et al., 2020)
Because the scope is focused on concept development and prototyping, the left side of the V-model will be used here as a guide to first define the system level goal, the system's design and functions which must be assigned to the components to be implemented. At the end, a simple proof of concept will be used to demonstrate an implementation that can be used as an example.
