The reason for a second type of resolution is one common flaw with voter resolution. If a majority of the worker nodes' results is equally incorrect, the voter would resolve it as a valid result. This is a common mode failure (CMF) and is defined by Hodson et al. (2024) as a failure that occurs due to a single event, design defect or violation of other independence assumptions. Mitra et al. (2000) describes several techniques to handle common mode failure, one aspect is to include methods that avoid CMF in the design and development process. It is important to mention here that any technique can only mitigate or reduce the effects of a CMF significantly, but cannot remove one entirely.

Following the principle of mitigating CMF in the design process, one choice will be proposed here by introduction of a plausibility score which in the diagram above was labeled as 'other resolution'. A basic rule set can be defined following the logic of how SHOP works. Because tasks are ordered into their sequence of execution, a probability can be defined per pair of any subsequent tasks A and B. If A comes before B, then a probability can be defined, e.g. 0.7-0.9. In the case of a task A before B, where A cannot happen before B, the probability is lower, e.g. 0.1-0.3.
For the resolution using a plausibility score, a weighted average will be used here. A single weight can be used for high probability cases and double weightage will be given to low probability cases. The effect of the latter intentionally lowers the score significantly to allow for a rejection of the voter's result. Repeating the same input would not yield a different result however, which is also this method's limitation because of DFS' deterministic behavior.
