# Hierarchical Task Networks

HTN is a paradigm in AI planning for automated planning. Classical planning focuses on finding sequence to get from point A to point B, while HTNs focus on high-level decomposition until high-level tasks become manageable, primitive subtasks \parencite{nau_shop_1999}. Four key components within HTN are tasks, methods, initial state and a goal. Tasks are the *what* of the plan. Primitive tasks are basic actions that can be executed in the environment. Non-primitive tasks are compound tasks, these are high-level tasks composed of several primitive tasks. Methods are the *how* and are the recipe telling the planner how to decompose a specific task into sub-tasks. The initial state describes the state that is to be planned for and holds information about the world at the beginning before planning starts. Decomposition is done recursively by the planner and stops when it has found a task set that can be directly performed by *planning operators*. The goal serves as the starting point for planning, which the planner then processes by assigning simple tasks in the task tree if conditions of the task are met. A task tree is the representation used by HTNs which contains all primitive and compound tasks in a hierarchy. Decomposition takes place when a compound task in the tree is reached during planning, which is then solved by a method that can fulfill the conditions and assigns simple tasks as defined in the method. To find a plan that is suitable for a given initial state and an HTN tree, there are several planners which can be used, e.g. probabilistic (Sherkat, Wortmann and Wortmann, 2025) or heuristics (Georgievski and Aiello, 2015). Two planners that serve as a starting point for an introduction into this subject are SHOP and SHOP2. SHOP is “Simple Hierarchical Ordered Planner” which decomposes tasks recursively into directly executable primitive tasks exactly in the order they are to be executed. This significantly reduces complexity in the decision making for task sequences because the planner knows at each step the current state of the world, thus removing uncertainty in planning. SHOP2 adds the possibility of partial ordering where subtasks from different compound tasks can be interleaved which means that the sequence of executing their subtasks is not strictly a total order and can be mixed. In total order, one compound task must be fully decomposed and solved before the next one can be solved by the planner. \parencite{nau_shop2_2003}

SHOP planners use depth-first search (DFS) algorithm in the traversal of their task trees (Nau et al., 1999), which provides a deterministic search algorithm when used with a fixed adjacency structure (Lammich & Neumann, 2015) and a fixed starting vertex. An adjacency list, as defined by Tarjan (1971), contains all vertices $w$ such that $(v,w) \in E$ of a graph $G = (V,E)$ with $V$ vertices and $E$ edges. In other words, an adjacency list contains all the neighbors of one vertex $v\in V$. An adjacency structure contains all adjacency lists of a graph $G$. (_Note 9/11)_ In practical application, what follows is that a SHOP planner runs a defined list of tasks and methods in an order set during offline development, which may be required when multiple methods must be searched when given a complex initial world state. The reason to use SHOP in this work is because DFS creates reproducible outcomes under the defined conditions and SHOP's total order imposes a reproducible process in its preceding steps, which aligns in principle to the definition of determinism as stated in EASA (2022, Sec. 4) in regard to the repeatability of outcome.
