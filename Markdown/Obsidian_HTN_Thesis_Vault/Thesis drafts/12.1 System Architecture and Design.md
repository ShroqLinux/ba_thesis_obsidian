As an initial approach, it is useful to consider what is generally required for a TMR node cluster before specifying it further to a HTN. For this, it will be defined which modes of system operation must be considered and what functions these modes need to execute. The functions then can be mapped to components that need to interact in the system. After this, interfaces for interaction of said components can be defined.

Firstly, it is to be defined what an expected normal mode of operation must fulfill and which functionality it performs. The second mode of operation is the response to a failure that has occurred during normal operation. In any distributed system, this requires state synchronization in the system. Dependent on the type of synchronization that is used in the system (Viotti and Vukolić, 2017), it needs to be defined which components must be synchronized and in what manner. This will be defined later in component definition. As a start, three system states will be defined: Active, Failure and Standby.

Active is the expected system behavior during normal operation where input data is received, passed to HTN worker nodes, a result is determined and forwarded as output. Generally in a distributed system (especially complex ones), there are many different failures that are possible (Maurya and Kumar, 2020). Hence it is necessary to define which types of failures will be analyzed here. The scope will focus on node failure, specifically the worker nodes of the TMR cluster because of the main question in this writing on failure mitigation. The third system state is Standby which would be during system recovery where all other components must wait until normal operation may resume, upon which the system transitions again to Active state.
