| **2026-08-10**     | Baseline TMR before advanced variants — prioritize foundational TMR behavior analysis over complex dynamic/adaptive schemes (e.g., Bonna et al., Hamilton et al.) to establish baseline properties first                                                                                         |                                                                                                                                                              |

| **2026-08-13**     | Scope exclusion of N-Version Programming — ruled out software diversity due to excessive lifecycle and process costs; focus remains on homogeneous replicas                                                                                                                                      |                                                                                                                                                              |
| **2026-08-19**     | Multi-tier state synchronization models — mapped synchronization primitives by execution boundary: thread signaling/barriers (single process), pooling sink process (multi-process), and coordinator VM/node (multi-node)                                                                        |                                                                                                                                                              |
| **2026-08-19**     | Fault detection via watchdogs and heartbeats — incorporated watchdog timers (detecting infinite planning recursion/hangs) and heartbeat signals alongside the majority voter                                                                                                                     |                                                                                                                                                              |
| **2026-08-20**     | Deterministic DFS over stochastic/heuristic planners — formal exclusion of heuristic and randomized planners to ensure predictable fallback mechanisms and alignment with DO-178C certification principles                                                                                       |                                                                                                                                                              |
| **2026-08-20**     | Offline pre-configured static network topology — excluded dynamic network discovery/routing to reflect safety-critical avionics standards with closed-world determinism                                                                                                                          |                                                                                                                                                              |
| **2026-08-25**     | Axiomatic guaranteed message delivery via avionics bus standards — justified treating message delivery as solved/guaranteed by citing established deterministic standards (MIL-STD-1553, ARINC 664/AFDX, ARINC 429), formally decoupling network transport issues from the planning thesis scope |                                                                                                                                                              |
| **2026-08-27**     | Excluded software process engineering and formal verification methods (e.g., DO-178C, ISO 26262 coding guidelines) from scope to maintain focus strictly on architectural reasoning.                                                                                                             |                                                                                                                                                              |
| **2026-08-27**     | Excluded voter threshold matching and formally assumed that a degraded DMR (post-node failure in a TMR cluster) cannot resolve conflicts internally.                                                                                                                                             |                                                                                                                                                              |
| **2026-08-27**     | Confirmed that the proof of concept utilizing virtualization adequately reflects physical node hardware behavior, eliminating the need to run the implementation on real hardware.                                                                                                               |                                                                                                                                                              |
| **2026-08-28**     | Defined watchdog timer limits by calculating Worst-Case Execution Time (WCET) based on the CPU cycles required for only the longest possible DFS search path, plus a buffer $\epsilon$.                                                                                                          |                                                                                                                                                              |
| **2026-09-01**     | Hash-based voting and $O(n)$ diagnostics — voter will compare hashes of tasks/parameters rather than raw sets; chose $O(n)$ array hashing to allow for diagnostic visibility of where errors occur.                                                                                              |                                                                                                                                                              |
| **2026-09-22**     | Control Plane / Data Plane separation — formally split the architecture, defining the dispatcher, monitor, and voter as the control plane (acting as arbiters), and the worker nodes/actuators as the data plane.                                                                                |                                                                                                                                                              |
| **2026-09-22**     | Push-style heartbeat monitor — selected a push-style monitor to reduce bus bandwidth, defining the timeout duration as multiples of the period $T = \frac{1}{f}$ based on avionic bus constraints.                                                                                               |                                                                                                                                                              |
| **2026-09-22**     | Actuators excluded from monitoring — restricted monitoring scope strictly to planner nodes, treating actuators as a black-box component.                                                                                                                                                         |                                                                                                                                                              |
| **2026-09-22**     | Empirical watchdog limit for PoC — justified using a statistical approximation for the watchdog timer in the Python (GTPyhop) PoC, while defining static max-depth cycle counts as the formal real-time WCET.                                                                                    |                                                                                                                                                              |
| **2026-09-25**     | Rejection of Threshold / Inexact Voting — formally excluded similarity scores and partial ordering (SHOP2), ensuring strict determinism and preventing the voter from being tricked by equally incorrect nodes fulfilling a threshold constraint.                                                |                                                                                                                                                              |
| **2026-10-05**     | Dispatcher ingress monitoring — explicitly removed a central server requirement to reduce hardware footprint; delegated read-only verification (verifying input data from external subsystems) directly to the dispatcher.                                                                       |                                                                                                                                                              |
| **2026-10-06**     | Separation of state synchronization scopes — decoupled state synchronization intended for error recovery (initiated by the monitor) from state synchronization for intended behavior (handled by the dispatcher).                                                                                |                                                                                                                                                              |
| **2026-10-08**     | Atomic vs. Progressive Dispatch — established two distinct dispatch models to accommodate physical actuator constraints, noting they can coexist depending on task criticality and priority.                                                                                                     |                                                                                                                                                              |
| **2026-10-08**     | Liveness ACKs on shared inter-system buses — excluded high-frequency heartbeats for external communication to reduce bus occupancy; repurposed acknowledgements (e.g., MIL-STD-1553C Status Word) strictly for liveness confirmation rather than message delivery verification.                  |                                                                                                                                                              |
| 2026-10-15         | Use Model-Based Systems Engineering (MBSE) to structure the system definition.                                                                                                                                                                                                                   | Establishes system functions, component responsibilities, interfaces, states, and failure responses before prototype implementation.                         |
| 2026-10-15         | Keep the TMR architecture concept independent of specific hardware or software implementation choices.                                                                                                                                                                                           | The architecture defines redundancy and coordination responsibilities without prescribing a particular implementation technology.                            |
| 2026-10-27         | Define explicit system states: Active, Failure, and Standby.                                                                                                                                                                                                                                     | Makes operational status and transitions during failure handling and recovery explicit.                                                                      |
| 2026-10-27         | Identify three synchronization points during normal execution: input distribution, worker planning results, and voter resolution of the selected result.                                                                                                                                         | Clarifies coordination boundaries between the dispatcher, replicated workers, and voter.                                                                     |
| 2026-10-27         | Separate majority agreement from plan plausibility validation.                                                                                                                                                                                                                                   | Agreement between replicas does not by itself establish that a plan is plausible, particularly in the presence of common-mode failures.                      |
| 2026-10-29         | Use heartbeat timeouts to detect worker failures and initiate a coordinated halt response.                                                                                                                                                                                                       | Allows the monitor to detect missing worker heartbeats and trigger failure handling.                                                                         |
| 2026-10-29         | Keep the system in Standby until restart coordination and recovery synchronization are complete.                                                                                                                                                                                                 | Prevents normal operation from resuming before the replicas reach a coordinated restart point.                                                               |
| 2026-11-01         | Assign the dispatcher both the starting and ending synchronization keyframes: it waits for all external input data, forwards input and initial world state to the workers, and makes the final decision on forwarding the plan to the actuators.                                                 | Concentrates entry and exit coordination in one control-plane component, so workers start at nearly the same time and only resolved plans leave the cluster. |
| 2026-11-01         | Restrict the voter to task plan verification only, with the voter waiting for the plans of all three worker nodes before verifying agreement.                                                                                                                                                    | Keeps the voter a pure arbiter with a minimal function set; waiting for all three plans forms the second synchronization point.                              |
| 2026-11-01         | Route the voter's verification result only to the worker nodes, which forward verified task sets to the dispatcher (no direct voter–dispatcher communication).                                                                                                                                   | Preserves the control/data plane separation and the voter's role as arbiter.                                                                                 |
| 2026-11-01         | Use a common watchdog timer for all worker nodes.                                                                                                                                                                                                                                                | All nodes run the same HTN task tree, so their maximum possible search execution times are expected to be similar.                                           |
| 2026-11-01         | On watchdog expiry, the monitor multicasts the failure to all components, including the affected node.                                                                                                                                                                                           | The faulty node would otherwise not know about its own fault and could not start its restart.                                                                |
| 2026-11-01         | In Standby, workers cancel their active computation and reset to await new input; the dispatcher stops forwarding new input.                                                                                                                                                                     | Brings all components to a common waiting state before recovery.                                                                                             |
| 2026-11-01         | On failure detection, the voter discards all task sets already received and waits for new ones.                                                                                                                                                                                                  | Prevents false failure masking, where a 2-out-of-3 vote over the healthy nodes' plans would hide the detected failure.                                       |
| 2026-11-01         | The restarted node multicasts its availability; all components then return to Active and the dispatcher resends its current input to the workers.                                                                                                                                                | A self-announced restart gives one clear trigger for resynchronizing and resuming normal operation.                                                          |
| 2026-11-01         | Scope assumption: node restart always completes successfully (no indefinite wait).                                                                                                                                                                                                               | Bounds the recovery analysis; restart failure handling is out of scope.                                                                                      |
