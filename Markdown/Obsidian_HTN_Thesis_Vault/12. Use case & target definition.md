
The goal of a distributed architecture in a broader context is to have some benefit through system capabilities which a single unit solution cannot fulfill. A single HTN system is also a single point of failure (SPOF), this applies to any system that is implemented as only one component. Since the writing is focussed specifically on safety-critical systems, the main question is how coordination can be done effectively for a redundantly designed HTN. This entails relevant components, their capabilities and trade-offs for real-world implementations.
As a method of work, some principles from model-based systems engineering will be used to serve as a framework in guiding the process to find a solution concept. As stated just now with the problem of a SPOF, this defines the *why* in this process and *what* the solution must accomplish.

_Note 15/10/26: MBSE method of work, system definition_

The next step is to state *how* the system-level problem of a SPOF can be solved, which is done by introducing triple modular redundancy (TMR). The decision for TMR is rooted in the common use within avionic and other safety-critical domains, this applies to both hardware and software systems. Hence the architecture defines no restriction on a concept level of how TMR is implemented in its technical implementation, both software and hardware may be viable depending on the specific system. Later, several types of redundancy concepts in both hardware and software in existing literature will be discussed in more depth (_Note: use earlier notes as topic chapters_).

Using the model above, it is simpler to define what other components are necessary to use TMR as a part of the process to mitigate a possible SPOF. Input would come from other systems, e.g. sensors, sub-systems, etc., and needs to be received by the process. The process then passes forward its output to other sub-systems, e.g. actuators.
For the functional logic, the basis for TMR is to use a voter for masking faults. One principle found in best practices can be applied here, by providing each component only with necessary information which it requires for the functions it is defined for.

Both coordination and communication in distributed computing have been extensively researched, Lamport (1978) laid the foundation for logical clocks, "happened before" relation and vector clocks. Same can be said about lower level communication including but not limited to Remote Procedure Calls (RPC) and Remote Method Invocations (RMI) (Tanenbaum and Van Steen, 2017).
This shifts the focus from coordination and communication which is relevant to the foundational concepts of distributed computing to the context of how both need to be designed for an architectural concept of a distributed hierarchical-task-network. As an initial approach, it's useful to consider what is generally required for a redundant node-cluster before specifying it further to an HTN.
